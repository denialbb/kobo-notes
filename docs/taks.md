**Goal**  
Eliminate cut-off and missing symbols (particularly ε, ∑ and ∫) in SVGs generated by MicroTeX from Markdown/LaTeX snippets, then establish an automated, agent-assisted debugging pipeline that reliably detects remaining visual defects before the SVGs are embedded in HTML for KOReader on Kobo devices.

**Task List**

1. **Verify and correct MicroTeX math-font configuration**
   - Confirm that a complete OpenType math font (Latin Modern Math, XITS Math or STIX Two Math) together with its matching CLM data file is present and registered.
   - Generate any missing CLM file with the supplied FontForge script:  
     `fontforge -lang=py -script otf2clm.py /path/to/MathFont.otf true /path/to/output.clm`
   - Register the font at initialisation or via the API:  
     `\addmathfont{name}{/path/to/font.otf}{/path/to/font.clm}` followed by `\mathversion{name}`.
   - Force display style where large operators are required (`\displaystyle` or `\everymath{\displaystyle}`).
   - Render the minimal test expression  
     `\displaystyle\sum_{i=1}^{n}\epsilon_i=\int_0^1 f(x)\,dx`  
     and confirm that ε, ∑ and ∫ appear correctly.

2. **Audit resource packaging for the KOReader plugin**
   - Ensure the chosen math font and its CLM file are correctly packaged and discoverable at runtime inside the plugin.
   - Enable MicroTeX logging (`HAVE_LOG`) or the `\debug` command on a failing snippet and inspect the symbol-lookup and box-tree output for missing character codes.

3. **Establish an automated rasterisation step**
   - After MicroTeX produces an SVG, convert it to a high-resolution PNG (2×–4× the intended display size) using one of:  
     `rsvg-convert`, `cairosvg`, Inkscape CLI, or a headless Chromium/Playwright render.
   - Optionally generate a second PNG with a coloured background or border so clipping is immediately visible.
   - Store both the original SVG and the PNG(s) together with the source LaTeX snippet.

4. **Add static SVG analysis**
   - Parse each SVG and extract the declared `viewBox`, width and height.
   - Compute the tight bounding box of all graphical content and flag any overflow relative to the viewBox.
   - Detect empty text elements, unresolved font references or missing operator glyphs.
   - Libraries that support these checks include `svgelements`, `svglib` or a lightweight XML + geometry script.

5. **Build the agent-assisted debugging loop**
   - Maintain a regression corpus of previously failing LaTeX snippets.
   - For every new or failing snippet:  
     a. Generate SVG → rasterise → run static checks.  
     b. Present the PNG(s), original LaTeX, raw SVG and check results to a vision-capable agent.  
     c. Instruct the agent to report (i) visible cut-off or missing symbols, (ii) probable root cause (tight viewBox, incomplete font, path-precision artefact, etc.), and (iii) concrete remediation steps.
   - Optionally regenerate the SVG with the suggested parameters and re-validate.

6. **Harden the generator against residual defects**
   - Enlarge the viewBox by a fixed margin (or add explicit padding) after MicroTeX generation.
   - Prefer path-based output for critical large operators when the font still proves unreliable.
   - Keep the regression suite up to date and re-run it after any change to MicroTeX, fonts or packaging.

7. **Integrate into the KOReader plugin workflow**
   - Insert the rasterisation + static-analysis + agent-review steps into the existing Markdown-to-SVG pipeline so that only validated SVGs are embedded in the final HTML.
   - Log every failure together with the agent diagnosis for later review.

**Supporting Notes**

- Missing ε, ∑ and ∫ are almost always caused by an incomplete or unregistered math font/CLM pair; correcting that configuration resolves the majority of symbol-loss cases.
- Rasterisation to PNG is required for reliable visual inspection by agents; pure SVG analysis is a useful complement but cannot substitute for a fixed visual result.
- KOReader’s SVG engines have known limitations with text and complex glyphs, therefore every generated SVG should be validated against the same rendering path used on the device whenever possible.

Execute the tasks in the order listed. Once steps 1–2 are complete, the remaining automation (steps 3–7) can be implemented incrementally and will continuously surface any residual cut-off or missing-symbol defects.
