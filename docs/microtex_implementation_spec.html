MicroTeX Integration

Complete Implementation Specification & Architecture Design for KOReader Markdown Plugin

1. Architecture Overview

The implementation will replace the current C-mock with a robust C++ wrapper that statically links against the real MicroTeX library. The pipeline ensures smooth rendering of LaTeX strings into SVG files suitable for e-ink displays.

Data Flow:
KOReader (Lua) → FFI (math_renderer.lua) → C Wrapper (microtex_wrapper.cpp) → MicroTeX Engine (C++) → SVG File

2. Implementation Plan

1 Submodule Integration

We will add the official MicroTeX repository as a Git submodule to ensure we track upstream changes while keeping the code self-contained.

git submodule add https://github.com/X-Wei/microtex.git plugins/markdownreader.koplugin/microtex

2 Font Asset Management

MicroTeX requires pre-processed font data (.clm files) to compute glyph metrics. We will include a default math font (e.g., lm-math.clm) inside the plugin's resource directory. The math_renderer.lua will pass the absolute path of this font to the initialization function.

3 The C++ Wrapper (microtex_wrapper.cpp)

We will implement a clean C-ABI wrapper around the MicroTeX C++ API. This ensures LuaJIT's FFI can seamlessly invoke the engine.

Function Signature Responsibility
void microtex_init(const char* clm_font_path) Initializes the microtex::MicroTeX engine and registers the base font.
int microtex_render_to_svg(const char* latex, const char* out, float size, float pad) Parses the LaTeX string, executes the SVG graphics 2D context, and writes the output. Returns 0 on success.
void microtex_release() Releases memory allocated by the MicroTeX engine to prevent memory leaks on plugin exit.

4 Build System Modernization

The current Makefile will be updated to handle a two-stage build process for cross-compiling to the Kobo (ARMhf):

  1. MicroTeX Static Library: Use CMake to compile MicroTeX into libmicrotex.a, disabling unused features (e.g., GTK/Qt rendering backends) to keep the binary small.
  2. Shared Object: Compile microtex_wrapper.cpp and statically link it with libmicrotex.a to produce the final libmicrotex.so.
# Example CMake configuration for cross-compiling MicroTeX
cmake -DCMAKE_TOOLCHAIN_FILE=../kobo-toolchain.cmake \
      -DBUILD_SHARED_LIBS=OFF \
      -DUSE_SVG=ON \
      ../microtex

3. Error Handling & Edge Cases

  • Parse Failures: If MicroTeX throws a parsing exception (e.g., invalid LaTeX syntax), the wrapper will catch the C++ exception, log the error to stderr, and return a non-zero exit code. The Lua layer will gracefully fallback to displaying the raw string.
  • Font Missing: If the .clm font path is invalid, initialization will fail early. The Lua module will verify file existence before calling microtex_init.
  • Memory Constraints: The microtex_release() function will be bound to KOReader's plugin lifecycle hooks (e.g., onCloseWidget or plugin teardown) to ensure heap memory is freed when the reader is closed.
